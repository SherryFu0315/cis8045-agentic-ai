Project

One agent service per team, built over seven weeks and defended on the last day.

What you are building

Teams of four take one bounded job that a person does today and build an agent service that does it: one user, one workflow, a limited set of tasks, and a human in charge of anything irreversible. The demo is the smallest part of the work. The grade rests on the package a company would need before letting the agent near real work.

Where a sponsor brief is available, the team works from it. Otherwise the team brings a problem from a current or former workplace, with data it is allowed to use: public, synthetic, or de-identified with the owner's permission. No team connects to a production system.

Deliverables

  1. A served agent. On the code path, an endpoint built with LangGraph. On the no-code path, an agent built in Fleet, LangSmith's no-code builder, that another application calls. Either way it uses at least two tools and runs on free tiers.
  2. An evaluation report. A golden set of at least twenty cases, pass^k results, an error analysis of the failures, and a judge calibrated against human labels.
  3. A security review. The injection surface, a lethal-trifecta check, the approval gates, and what the logs would show after an incident.
  4. An operations sheet. Cost per task, latency, what breaks, and who is responsible when it does.
  5. A decision memo. Two pages for an executive: deploy, extend the pilot, or stop, with the numbers behind the recommendation.
  6. The final presentation. Ten minutes of demo and questions in front of a panel that plays the buyer.
  7. An individual reflection with an AI-use disclosure.

Roles

Each team assigns four roles and keeps them for the term: builder, evaluator, red team and governance, and product owner. The builder writes the code or configures Fleet. The evaluator owns the golden set and the error analysis. Red team and governance owns the security review and the approval design. The product owner owns the brief, the memo and the final presentation. Everyone reads traces and everyone writes.

Two build paths

The code path uses Python, LangGraph and LangSmith. Coding agents such as Claude Code or Codex are allowed, and the builder should expect a short oral check in which I pick a trace and ask what the code did and why. The no-code path uses LangSmith Fleet plus the small bridge application from CIS 4394, which lets another program call a Fleet agent. Both paths produce the same seven deliverables and are graded on the same rubric.

How it is graded

The project is 35 percent of the course grade: served agent 10, evaluation report 10, security review 5, decision memo 5, presentation 5. The weekly one-page deliverables are graded separately and add up to 25 percent. Every component is read against the four questions on the course page and against six requirements every project must meet: free tiers only, at least two tools, a golden set of at least twenty cases with pass^k results, a security review, an honest list of limitations, and a memo an executive could act on.
